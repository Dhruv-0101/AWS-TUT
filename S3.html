1. 🪣 What is Amazon S3? (Simple Storage Service & Infinite Capacity)

Instructor Gaurav Sharma's Core Service Definition:

Virtually Infinite Object Storage:

"Amazon S3 stands for **Simple Storage Service**. It is an object storage service offering industry-leading scalability, data availability, security, and performance.

2. 💻 Developer Use Cases — Stateless Architecture & Media Streaming

Application Developer Implementation Scenarios:

  • Stateless Web Application Architecture: Offloading user-uploaded profile pictures and documents from EC2 web servers directly to S3. If an EC2 server crashes or auto-scales down, zero user files are lost!

4. 💰 Storage Classes & 20-Year Hospital Record Cost Optimization

Real-World Retention Cost Dilemma:

THE 20-YEAR DATA RETENTION COST PROBLEM:

"Imagine a hospital or hotel that has been generating patient prescriptions or billing receipts for 20 years. Legally, the hospital must retain 20 years of medical records.
If all 20 years of data are stored in active high-cost storage, the monthly bill would be astronomical!

5. ❄️ S3 Standard vs Standard-IA vs Glacier Deep Archive

Tiering Access Profiles:

  1. S3 Standard: High frequency access, millisecond retrieval, active web files.
  2. S3 Standard-IA (Infrequent Access): Lower storage cost, small retrieval fee for files accessed once every few months.
  3. S3 Glacier / Glacier Deep Archive: Lowest cost storage vault for multi-year archival (retrieval takes 3-5 hours or minutes via expedited mode).

10. 🌏 S3 Bucket Architecture & Regional Placement

Containers & Region Selection:

  1. Data in S3 is stored in top-level containers called **Buckets**.
  2. Every S3 bucket is created in a specific AWS Region (e.g., `ap-south-1` Mumbai or `us-east-1` N. Virginia).

11. ⚠️ Global Unique Bucket Naming Rule (`BucketAlreadyExists` Constraint)

The #1 S3 Golden Rule:

MUST-KNOW S3 BUCKET NAMING RULE:

Even though an S3 bucket is created in a specific region, **S3 BUCKET NAMES MUST BE GLOBALLY UNIQUE ACROSS ALL AWS ACCOUNTS WORLDWIDE IN ALL REGIONS!**
If User A creates a bucket named `my-company-backup` in N. Virginia, NO user anywhere on Earth can create a bucket named `my-company-backup` in Mumbai or any other region! AWS returns `BucketAlreadyExists` error.

12. 📄 Objects vs Files (Metadata, Keys & Object URLs)

Object Architecture:

  • Files stored in S3 are called **Objects** (up to 5 TB max per single object).
  • An Object consists of: Key (filename/path), Value (data bytes), Metadata (content-type, tags), and a unique Object URL.

14. ❓ Interview Questions

Q1. What is the global naming requirement for Amazon S3 Buckets?

S3 Bucket Names must be globally unique across all AWS accounts worldwide in all regions. No two AWS accounts on Earth can share the same S3 bucket name.

Q2. How does Amazon S3 help in building stateless web applications?

By storing user-uploaded files and media in S3 instead of local EC2 server disks, web nodes remain stateless and can be scaled, terminated, or replaced without losing application data.

Q3. What is the "Requester Pays" feature in Amazon S3?

Requester Pays shifts the network data transfer (download bandwidth) costs from the bucket owner to the requesting user's AWS account.

Q4. What is the maximum size of a single object that can be stored in Amazon S3?

The maximum size of a single object in Amazon S3 is 5 Terabytes (5 TB).

Q5. How can you minimize storage costs for multi-year regulatory data (e.g. 20-year medical records)?

By configuring S3 Lifecycle Policies to transition data from S3 Standard to S3 Standard-IA, and finally archiving to S3 Glacier Deep Archive for ultra-low storage cost.

1. ⚠️ Deep-Dive S3 Naming Rules & Syntax Violation Errors

Instructor Gaurav Sharma's Bucket Naming Rules Testing:

S3 BUCKET NAMING SYNTAX CONSTRAINTS:

  • Uppercase Characters: `Gaurav-Youtube-V1` → FAIL! Error: "Bucket name must not contain uppercase characters."
  • Length Limits: Must be between 3 and 63 characters long.
  • IP Address Format: Bucket names CANNOT be formatted as an IPv4 address (e.g. `192.168.1.1`).
  • Leading / Trailing Hyphens: `-gaurav-youtube-v1` → FAIL! Error: "Bucket name must start and end with a lowercase letter or number."

2. 🔓 The Goal — Public Read Object Access over HTTPS

Objective: Configure the bucket policy so that any user anywhere on the internet can open direct HTTPS Object URLs (e.g. `https://gaurav-youtube-v1.s3.ap-south-1.amazonaws.com/image.png`) in their browser without encountering HTTP 403 `AccessDenied`!

3. 🛡️ Step 1 — Disabling "Block Public Access" Guardrail

  1. S3 Console → Select bucket gaurav-youtube-v1 → Click Permissions tab.
  2. Locate Block public access (bucket settings) → Click Edit.
  3. Uncheck Block all public access.
  4. Click Save changes → In confirmation modal, type "confirm" → Click Confirm.

4. ⚡ Step 2 — Opening AWS Policy Generator

Under Bucket policy → Click Edit → Click Policy generator link (opens AWS Policy Generator in a new tab).

5. 📜 Step 3 — Configuring Policy Generator Inputs (`s3:GetObject`, Principal `*`)

  1. Select Policy Type: Choose S3 Bucket Policy.
  2. Effect: Select Allow.
  3. Principal: Enter * (Wildcard representing anonymous internet users).
  4. AWS Service: Select Amazon S3.
  5. Actions: Search and check GetObject (s3:GetObject).
  6. Amazon Resource Name (ARN): Paste bucket ARN.

6. ❌ The Common ARN Formatting Trap (`arn:aws:s3:::bucket` vs `arn:aws:s3:::bucket/*`)

CRITICAL BUCKET POLICY ERROR & FIX:

If you paste raw bucket ARN arn:aws:s3:::gaurav-youtube-v1, AWS returns "Unknown Error / Action does not apply to resource" because s3:GetObject applies to objects inside the bucket, NOT the bucket container itself!

THE MANDATORY FIX:

You MUST append /* to the bucket ARN: arn:aws:s3:::gaurav-youtube-v1/*. This explicitly targets all objects inside the bucket!

7. 📄 Valid Public Read JSON Bucket Policy Document Structure

Complete JSON Policy Code:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::gaurav-youtube-v1/*"
    }
  ]
}

14. ❓ Interview Questions

Q1. What happens if you apply a Bucket Policy with `Action: s3:GetObject` on Resource `arn:aws:s3:::mybucket` without trailing `/*`?

AWS returns an error indicating the action does not apply to the resource. `s3:GetObject` requires object-level targeting, which is specified by appending `/*` (e.g. `arn:aws:s3:::mybucket/*`).

Q2. What two steps are required to make an S3 bucket's objects publicly readable over HTTPS?

1. Uncheck 'Block all public access' under Bucket Permissions. 2. Attach a JSON Bucket Policy granting `s3:GetObject` permission to Principal `*` on `arn:aws:s3:::bucketname/*`.

Q3. Do newly uploaded objects in a public bucket automatically become public, or do you have to configure each object individually?

Newly uploaded objects automatically inherit the bucket policy's public read permissions without needing individual object-level ACL modifications.

Q4. Which S3 bucket naming rule is violated by the name `My-Bucket-2026`?

S3 bucket names must not contain uppercase letters. `My-Bucket-2026` contains uppercase 'M' and 'B'.

Q5. What tool provided in the AWS Console helps construct valid JSON Bucket Policies?

The AWS Policy Generator.

1. 🔍 Navigating Object Properties in S3 Console

When you click on any uploaded object in the Amazon S3 Management Console, AWS presents a comprehensive Object Overview / Properties tab containing essential attributes:

  • Owner: The AWS Account Canonical User ID or IAM user that uploaded the file.
  • S3 URI: Unique S3 path format (e.g. s3://gaurav-youtube-v1/terraform.jpg) used by AWS CLI and SDKs.
  • AWS Region: The geographic region holding the bucket (e.g. ap-south-1 Mumbai).
  • Object ARN: Amazon Resource Name (e.g. arn:aws:s3:::gaurav-youtube-v1/terraform.jpg) used in JSON Bucket Policies and IAM permissions.
  • Last Modified: Exact timestamp of the latest object creation or replacement.
  • Size: Exact binary payload size (e.g. 271.4 KB).
  • Type / Content-Type: MIME type header (e.g. image/jpeg or application/json).
  • Object URL: Direct public HTTPS endpoint (e.g. https://gaurav-youtube-v1.s3.ap-south-1.amazonaws.com/terraform.jpg).

2. 🏷️ S3 Object Tags & Lifecycle Teaser

Instructor Gaurav Sharma demonstrates adding Object Tags (key-value metadata pairs attached to specific files):

💡 Real-World Production Use Case: Automated 7-Day Cleanup Policy

Imagine you want temporary files (like invoice PDFs or user upload previews) to auto-delete after 7 days to save S3 storage costs:

  1. Attach an Object Tag during upload: Retention = Temporary.
  2. Configure an S3 Lifecycle Rule targeting tag filter Retention = Temporary.
  3. Result: AWS automatically purges ONLY objects with tag Retention = Temporary after 7 days while preserving permanent production images!

3. 📊 System-Defined Metadata vs User-Defined Metadata

Every S3 Object maintains HTTP response headers and custom metadata attached as name-value pairs:

⚙️ System-Defined Metadata

Predefined HTTP headers managed by AWS or configured by the client:
• Content-Type (e.g. image/jpeg, video/mp4)
• Content-Disposition (e.g. inline or attachment)
• Cache-Control (e.g. max-age=3600)
• Content-Encoding (e.g. gzip)

👤 User-Defined Metadata

Custom key-value pairs stored with the object payload:
• Prefixed automatically by AWS as x-amz-meta-*
• Example: x-amz-meta-uploadedby: gaurav
• Example: x-amz-meta-department: devops
• Retained with the object until updated or overwritten.

4. 🧩 What is an ETag in Amazon S3?

Instructor Gaurav Sharma highlights the ETag (Entity Tag) property appearing in the Object Overview:

Definition: An ETag is an HTTP header returned by S3 representing an MD5 hash digest of the object's data.

• For standard single-part uploads, the ETag is the exact 128-bit MD5 checksum string (e.g. "5a38fc2834b6b6c...").
• Purpose: Used by client applications and browsers to verify file integrity and check if an object has changed without downloading the full payload.

The Key is the unique string name assigned to an object inside a bucket. Think of a bucket as a giant flat hash map Dictionary<Key, Payload>:

Q1. Do real directory folders exist inside Amazon S3 buckets? Explain how AWS Console shows folders.

No. S3 is a flat key-value namespace. AWS Console parses slash delimiters (`/`) in object key strings (e.g. `courses/gaurav/photo.jpg`) and visually renders prefixes as virtual yellow folder icons.

Q2. What is the Object Key for a file displayed in AWS Console as `/courses/gaurav/terraform.jpg`?

The Object Key is `courses/gaurav/terraform.jpg` and its prefix is `courses/gaurav/`.

Q3. What is the maximum size of a single object uploaded in a single HTTP PUT request to S3?

5 GB (Gigabytes).

Q4. How can you upload a 100 GB database dump file to Amazon S3?

By using S3 Multipart Upload, which splits the payload into parts (5 MB to 5 GB each), uploads them in parallel streams, and reassembles them into a single object up to 5 TB in size.

System-Defined Metadata consists of HTTP headers managed by AWS or configured by clients (like `Content-Type`), whereas User-Defined Metadata consists of custom key-value pairs stored with prefix `x-amz-meta-*`.

AWS Tutorials - 63 - S3 Versioning - What is Versioning - Prevent a Object from Deletion

1. 🧠 S3 Versioning Problem Statement — Overwrite Risk & Historical File Recovery

In standard S3 bucket operations, uploading a file with an identical object key (e.g. courses/1.png) permanently overwrites the existing object. Without versioning, previous versions are lost forever.

The Enterprise Use Case Dilemma:

Imagine uploading a document today, updating it 2 days later, and updating it again 3 days later under the exact same filename. If a auditor asks for the file as it existed 10 days ago, traditional unversioned storage cannot fulfill the request. S3 Versioning solves this natively by preserving every historical revision under the same object key.

2. 🪣 Bucket-Level Scope & S3 Console Navigation

Key Architectural Rule:

5. 🎛️ The `Show versions` Toggle Switch in S3 Console

Once Versioning is enabled on a bucket, S3 Console unlocks a new UI element:

  • `Show versions` Toggle (OFF): Displays only the latest / current version of each object, giving a clean flat view.
  • `Show versions` Toggle (ON): Expands the virtual tree to display every historical version of every file, along with Version IDs, creation timestamps, and Delete Markers!

6. 🔑 Demystifying S3 Key vs Version ID Architecture (`Key + Version ID` Map)

How Amazon S3 Handles Identical Filenames under Versioning:

S3 Internal Storage Lookup Engine:
Object Reference = Bucket Name + Object Key + Unique Version ID

Example:
Key: aws-course/1.png  │  Version ID: 3/L4kfiW5MYGUAz8... (Latest Version)
Key: aws-course/1.png  │  Version ID: g6Zx9P0qR1wT7v...  (Previous Version)
Key: aws-course/1.png  │  Version ID: null               (Pre-Versioning Initial Version)

S3 allows identical key strings because every version is internally indexed as a unique tuple (Key, VersionId).

7. 🏷️ Pre-Versioning Objects & The `null` Version ID

Important System Behavior:

What happens to files uploaded BEFORE versioning was enabled?

Existing objects uploaded prior to enabling versioning are assigned a special string Version ID: null. Once versioning is turned ON, subsequent uploads receive unique 32-character string GUID Version IDs.

8. 💰 Enterprise Cost Impact of S3 Versioning (Multi-Version Storage Charges)

CRITICAL AWS BILLING WARNING:

S3 Versioning does NOT compress or merge old files! If you upload ten 1 GB revisions of a database backup file under the same key, AWS S3 stores ten separate 1 GB objects and charges you for 10 GB total storage space! Always configure S3 Lifecycle rules to clean up or transition non-current versions to Glacier.

9. 🛡️ Accidental Deletion Protection — How S3 Delete Markers Work

What happens when a user deletes a file in a Version-Enabled Bucket with `Show versions` OFF?

  1. User selects 1.png → Clicks Delete → Types delete → Clicks Confirm.
  2. S3 Console shows: "Successfully deleted object".
  3. The Reality: S3 does NOT delete the actual file data! S3 creates a 0-byte system object called a Delete Marker and places it as the current/latest version!
  4. Any GET request without a Version ID hits the Delete Marker and returns an HTTP 404 Not Found error.

10. 🔄 Disaster Recovery Lab — Restoring "Deleted" Files by Deleting Delete Markers

How to recover an accidentally deleted file in S3:

  1. Go to S3 Bucket → Enable `Show versions` Toggle (ON).
  2. Locate the target file key (e.g. aws-course/1.png). You will see the top row marked as Delete marker.
  3. Select the Delete marker row ONLY → Click Delete.
  4. Confirm deletion by typing permanently delete → Click Delete Objects.
  5. Turn `Show versions` OFF → Result: The original file immediately reappears in the bucket as if it was never deleted!

11. 🗑️ Permanent Deletion of Specific Object Versions

To truly delete a file version permanently from an S3 bucket:

  • Enable Show versions (ON).
  • Select the specific Version ID row (or select all versions including Delete Markers).
  • Click Delete → Type permanently delete.
  • S3 permanently purges that specific Version ID from AWS storage hardware.

12. ⏸️ S3 Versioning States — Enabled vs Suspended (Why Versioning Cannot Be Disabled)

Architectural Rule for AWS S3 Bucket Lifecycle:

Can you Disable S3 Versioning after enabling it?

NO! Once versioning is enabled on an S3 bucket, it can NEVER be completely disabled back to unversioned state. It can only be transitioned to Suspended state. In Suspended state, existing versioned objects retain their version IDs, while new uploads overwrite `Version ID: null` objects.

14. ❓ Interview Questions

Q1. Can you disable Amazon S3 Versioning on a bucket once it has been enabled?

No. Once enabled, versioning can only be **Suspended**, not disabled. Suspended state stops creating new version IDs for new uploads while retaining all existing historical versions.

Q2. What is an S3 Delete Marker and how does it protect against accidental deletion?

When an object in a version-enabled bucket is deleted without specifying a version ID, S3 inserts a 0-byte Delete Marker as the current version. The file appears deleted, but the previous versions remain intact and can be restored by simply deleting the Delete Marker.

Q3. What Version ID is assigned to objects uploaded BEFORE S3 Versioning was enabled on the bucket?

They are assigned `Version ID: null`.

Q4. How does Amazon S3 Versioning impact AWS storage costs?

S3 charges for every stored version of an object. Storing 5 revisions of a 2 GB object incurs billing for 10 GB of total storage. Lifecycle policies should be configured to expire non-current versions.

Q5. How do you permanently delete an object from an S3 bucket with versioning enabled?

You must turn `Show versions` ON in the console (or pass the exact `--version-id` parameter in AWS CLI) and explicitly delete the specific version ID.
