AWS Tutorials - 51 - AWS IAM Service - Identity and Access Management

1. 🏢 The Real-World Delegation Problem (200-300 Employees)

Instructor Gaurav Sharma's Real-World Scenario:

The Single Administrator Bottleneck:

"Imagine managing an enterprise AWS cloud with 200 to 300 developers requesting EC2 instances, S3 storage buckets, VPC subnets, and Route 53 DNS records daily. A single cloud administrator cannot manually fulfill every request. You must hire specialized team members:
• **Person 1 (EC2 Admin):** Validates and provisions EC2 compute servers.
• **Person 2 (S3 Admin):** Manages object storage buckets.
• **Person 3 (Network Admin):** Manages VPCs, Lambda, and Route 53.
How do we give Person 1 EC2 access while preventing them from touching S3 buckets? **AWS IAM makes this possible!**"

2. 🛡️ Principle of Least Privilege

Core Security Rule:

"The **Principle of Least Privilege** dictates that every user, application, or service should be granted ONLY the minimum necessary permissions required to perform their specific job function, and nothing more. Granting full admin access to ordinary developers is an enterprise security risk!"

3. 🌐 IAM is a GLOBAL Service (No Region Selection Required!)

Key Architectural Fact:

GLOBAL VS REGIONAL SERVICES:

When you create an EC2 instance, S3 bucket, or VPC, you must select an AWS Region (e.g. `ap-south-1` Mumbai or `us-east-1` N. Virginia). However, **AWS IAM is a Global Service**! A user or policy created in IAM is automatically recognized across all AWS regions worldwide without needing regional replication.

AWS Authorization Rule:

EXPLICIT DENY DEFAULT:

In AWS IAM, every API request is **implicitly denied by default**. A newly created IAM user has 0 permissions until an administrator explicitly attaches an IAM policy granting `Allow` access to specific services!

14. ❓ Interview Questions

Q1. Is AWS IAM a regional or global service?

AWS IAM is a Global Service. All users, groups, roles, and policies created in IAM are recognized globally across all AWS regions without regional selection.

Q2. What permissions does a newly created IAM user have by default?

A newly created IAM user has zero permissions by default. AWS operates on an implicit default-deny security model until policies granting explicit `Allow` access are attached.

Q3. What are the key elements of an IAM JSON policy document?

`Version` (policy language version), `Statement` (array of rules), `Effect` (`Allow` or `Deny`), `Action` (list of API operations), and `Resource` (target ARNs or `*`).

Q4. What is the difference between programmatic access and AWS Management Console access for an IAM user?

Console access allows human users to sign into the AWS Web UI using a username and password. Programmatic access provides Access Keys (Access Key ID and Secret Access Key) for AWS CLI, SDK, and API calls.

Q5. What happens if a user with `IAMReadOnlyAccess` attempts to create a new user?

The request fails with an access denied API error because `IAMReadOnlyAccess` allows `iam:Get*` and `iam:List*` actions but explicitly lacks permission for `iam:CreateUser`.

1. 👥 Why Use IAM User Groups? (Scaling from 50 to 5,000 Employees)

Instructor Gaurav Sharma's Scalability Explanation:

The Administrative Scale Bottleneck:

"If your IT company grows from 50 to 5,000 employees, manually creating individual IAM users and attaching individual policy documents to each user becomes impossible to manage.
The Solution: Create **IAM User Groups** (e.g. `Admin`, `Developer`, `QA-Tester`). You attach the policy to the group ONCE. Whenever a new developer is hired, simply add their user account to the `Developer` group, and they instantly inherit all required permissions!"

2. 🛠️ Step 1 — Create IAM Groups (`Admin` & `Developer`)

  1. IAM Console → Left Navigation → User groups → Create group.
  2. Group 1 Name: "Admin".
    • Attach policy: Select AdministratorAccess (`Effect: Allow, Action: *, Resource: *`).
    • Click Create group.
  3. Group 2 Name: "Developer".
    • Attach policy: Select AmazonEC2FullAccess.
    • Click Create group.

3. 👑 Interview Focus 1 — Root User vs `AdministratorAccess` Policy

Crucial Interview Question Analysis:

CRITICAL INTERVIEW COMPARISON:

• **Root User:** Account owner identity (created with email address). Root credentials **CANNOT be restricted or denied by any IAM policy** within the account. Required for billing changes, closing AWS accounts, and emergency break-glass recovery.
• **IAM User with `AdministratorAccess`:** Has full API control over all AWS services, BUT can still be restricted or blocked by Organization Service Control Policies (SCPs) or explicit `Deny` policy statements!

4. 🧬 Principle of Group Policy Inheritance (Parent Group → Child User)

Inheritance Architecture:

"In AWS IAM, User Groups act as **Parents** and Users act as **Children**. When a user is added to a group, they automatically inherit every permission policy attached to the parent group. Updating a group's policy instantly updates permissions for all member users!"

5. 🛠️ Step 2 — Create User `testadmin` & Verify Group Inheritance

  1. IAM Console → Users → Add user → Name: "testadmin".
  2. Console access enabled → Custom password.
  3. Permissions options: Select Add user to group → Select Admin group.
  4. Click Create user.
  5. Inspect `testadmin` Permissions tab → Under *Permissions summary*, policy displays: AdministratorAccess (Attached from group: Admin). Proves inheritance works!

6. 🔗 Step 3 — Multi-Group Assignment (Adding `user-admin-dev` to 2 Groups)

  1. Users → Add user → Name: "user-admin-dev".
  2. Console access enabled.
  3. Permissions options: Check BOTH Admin AND Developer groups!
  4. Click Create user.
  5. Result: An IAM user can belong to multiple groups simultaneously (up to 10 groups), inheriting policies from all assigned groups!

7. ⚔️ Interview Focus 2 — Conflict Resolution: Explicit `Deny` vs `Allow`

Instructor Gaurav Sharma's Famous Interview Scenario:

THE CONFLICT SCENARIO:

Scenario: User X belongs to Group A (`S3-Allow`: grants full write/delete on S3) AND Group B (`S3-Deny`: contains an explicit `Deny` statement on `s3:*`). Can User X read or write to S3?
ANSWER: NO! USER X IS COMPLETELY BLOCKED!
In AWS IAM evaluation logic: **AN EXPLICIT DENY ALWAYS OVERRIDES ANY NUMBER OF EXPLICIT ALLOWS!**

8. 📜 IAM Evaluation Logic Flowchart (Explicit Deny > Explicit Allow > Default Deny)

The 3-Step IAM Decision Algorithm:

                    Incoming AWS API Request
                               │
                               ▼
                Is there an EXPLICIT DENY?
                ├── YES ──────► [DENIED ❌] (Final Rejection!)
                └── NO
                    │
                    ▼
                Is there an EXPLICIT ALLOW?
                ├── YES ──────► [ALLOWED ✅] (Access Granted!)
                └── NO ───────► [DENIED ❌] (Implicit Default Deny!)

12. ❓ Interview Questions

Q1. What is the difference between the Root User and an IAM User with `AdministratorAccess`?

Root User credentials cannot be restricted by any IAM policy or SCP in the account. An IAM User with `AdministratorAccess` has full API rights, but can still be restricted by Organization SCPs or explicit `Deny` policy statements.

Q2. If a user belongs to Group A (Allow S3) and Group B (Deny S3), what permission does the user have on S3?

The user has NO permission on S3. In AWS IAM policy evaluation logic, an explicit `Deny` statement in any attached policy overrides any number of explicit `Allow` statements.

Q3. Can an IAM user belong to multiple IAM User Groups simultaneously?

Yes. An IAM user can belong to multiple IAM User Groups simultaneously (up to 10 groups per user), inheriting policy permissions from all assigned groups.

Q4. What happens when you create a new user using "Copy permissions from existing user" where the source user belongs to a group?

AWS automatically adds the new user as a member of the source user's group, enabling the new user to inherit all current and future group policies.

Q5. Why are IAM User Groups preferred over attaching policies directly to individual users?

Groups centralize permission management. Updating a group's policy instantly applies the change across all member users, eliminating manual policy maintenance across thousands of employee accounts.

14. 🎓 IAM User Group Governance Takeaway

IAM User Groups provide scalable, maintainable identity governance across enterprise organizations, enforcing policy inheritance and strict explicit-deny policy evaluation rules.

AWS Tutorials - 53 - AWS IAM Service - Password Policy

1. 💸 Real-World Case Study — The ₹3 Lakh Crypto-Jacking Billing Disaster

Instructor Gaurav Sharma's Real Security Warning:

THE COMPROMISE DISASTER:

"A real case study from a friend's company: An IAM user account password was leaked via an insecure channel. A hacker compromised the account and launched high-performance GPU/CPU EC2 instances across multiple regions to mine cryptocurrency 24/7.
In just **2 days**, the company received a massive **₹3 Lakh ($3,600+) AWS bill**!
Even worse: A hacker could terminate your core production databases and delete all application backups. **Securing IAM authentication is a top priority!**"

2. ⚠️ Attack Vectors — Brute Force, Dictionary Attacks & Keyloggers

Common Password Attack Methods:

  • Brute Force Attack: Automated software trying millions of rapid character combinations (`aaaa`, `aaab` ... `zzz`).
  • Dictionary Attack: Using pre-compiled wordlists containing millions of popular weak passwords (`Password123`, `Admin@2024`).
  • Keyloggers (Malware): Hidden background scripts or `.exe` malware recording physical keyboard keystrokes and emailing credentials to attackers.

3. 🛡️ Why Custom Password Policies are Mandatory in Enterprise AWS Accounts

Default AWS password policies are basic. Enterprise security standards require configuring strict custom password rules in IAM Account Settings to defeat dictionary attacks and force regular credential hygiene.

4. 🛠️ Step 1 — Navigate to IAM Account Settings & Password Policy

  1. IAM Console → Left Navigation → Account settings.
  2. Under *Password policy*, click Edit.
  3. Select Custom.

5. 📏 Minimum Password Length (16+ Characters)

Setting Length Thresholds:

  1. Set Minimum password length to 16 characters (configurable from 6 to 128 characters).
  2. Exponential math makes 16-character complex passwords computationally impossible to crack via brute force!

6. 🔡 Mandatory Character Complexity Rules (Upper, Lower, Numbers, Special Characters)

Enable Required Character Options:

  • Check Require at least one uppercase letter (`A-Z`).
  • Check Require at least one lowercase letter (`a-z`).
  • Check Require at least one number (`0-9`).
  • Check Require at least one non-alphanumeric character (`!@#$%^&*()`).

7. ⏱️ Password Expiration & Automatic 30-Day Rotation

  1. Check Enable password expiration.
  2. Set Password expiration period to 30 days (configurable from 1 to 1,095 days).
  3. After 30 days, the user is forced to set a fresh password upon sign-in.

8. 🔄 Preventing Password Reuse (Remembering Last 15 Passwords)

  1. Check Prevent password reuse.
  2. Set Number of passwords to remember to 15.
  3. Blocks lazy users from resetting their expired password back to an old password!

9. 👤 Self-Service Password Resets ("Allow users to change their own password")

Check Allow users to change their own password so employees can reset expired passwords without opening IT helpdesk tickets.

10. ⌨️ Cyber Security Awareness — Why Banking Sites Use Virtual Keypads

Keylogger Mitigation Insight:

Why Virtual On-Screen Keyboards Exist: Online banking portals use mouse-clickable virtual keypads to defeat physical keyboard keylogger malware. Clicking on-screen buttons generates no hardware keyboard interrupts!

11. 🔐 Introduction to Multi-Factor Authentication (MFA)

The Ultimate Defense Layer:

"Even if a keylogger captures an administrator's password, **Multi-Factor Authentication (MFA)** adds a 2nd physical barrier. Logging in requires 1) Something you KNOW (Password) + 2) Something you HAVE (Physical phone or Google Authenticator MFA code)."

12. 📊 Password Policy Comparison Matrix

Setting AWS Default Policy Enterprise Strong Policy
Minimum Length 8 Characters 16+ Characters
Character Diversity 3 of 4 Types All 4 Types (Upper, Lower, Number, Symbol)
Password Expiration Never Expires Expires every 30 Days
Reuse Prevention Disabled Remembers last 15 Passwords

13. ❓ Interview Questions

Q1. How do you enforce custom password requirements across all IAM users in an AWS account?

Navigate to IAM Console -> Account settings -> Edit Password policy, and define custom rules for minimum length, character diversity, expiration periods, and password reuse prevention.

Q2. Why is password reuse prevention important in IAM password governance?

Preventing password reuse (e.g. remembering the last 15 passwords) stops employees from toggling back to old, potentially compromised passwords when forced to rotate expired credentials.

Q3. What is a keylogger and how does MFA mitigate keylogger credential theft?

A keylogger is malware that records keyboard inputs to steal passwords. MFA mitigates this because even if an attacker steals the password, they cannot log in without the 2nd factor (the time-sensitive MFA code on a physical mobile device).

Q4. What is the recommended minimum password length for production AWS IAM accounts?

Industry security frameworks (NIST / AWS Well-Architected) recommend a minimum password length of 16 characters combined with character complexity rules.

Q5. How can IAM users change their expired passwords without contacting an AWS administrator?

By enabling the `"Allow users to change their own password"` option in IAM Account Settings, users can perform self-service password updates directly from the AWS Console sign-in page.

AWS Tutorials - 54 - AWS Multi Factor Authentication - AWS MFA

1. 🔐 What is Multi-Factor Authentication? (Factor 1 + Factor 2)

Instructor Gaurav Sharma's Security Architecture Breakdown:

The 2-Factor Barrier:

"Even if an attacker steals your password via keylogger malware or dictionary attacks, they CANNOT sign into your AWS account without the 2nd physical factor!
• **Factor 1 (Something you KNOW):** Root Email / IAM Username + Password.
• **Factor 2 (Something you HAVE):** A physical smartphone or tablet generating a 6-digit Time-based One-Time Password (TOTP) that changes every 30 seconds."

2. 🌐 Global Scope Reminder — MFA Configuration Across Regions

IAM Security settings apply **Globally**. Enabling MFA on your root user protects access to all AWS regions worldwide simultaneously.

3. 🛠️ Step 1 — Navigate to Security Credentials & Assign MFA

  1. Top Right Header -> Click your Account Name -> Select Security credentials (or IAM Dashboard -> Assign MFA).
  2. Under *Multi-factor authentication (MFA)* -> Click Assign MFA device.
  3. Device name: Enter custom label e.g., "MyTablet" or "AdminPhone".
  4. MFA Device Type: Select Authenticator app (TOTP app on Android / iOS).
  5. Click Next.

4. 📱 Selecting Authenticator App (Google Authenticator, Authy, Microsoft)

Install a free TOTP Authenticator app on your smartphone or tablet from Google Play Store or Apple App Store (e.g. Google Authenticator or Authy).

5. 📸 Step 2 — Scanning the AWS Console QR Code

  1. On AWS Console screen -> Click Show QR code.
  2. Open Google Authenticator app on mobile device -> Tap Scan a QR code.
  3. Align mobile camera with computer screen to scan secret seed key automatically.

6. ⏱️ Dual Consecutive TOTP Code Verification Rule (Code 1 & Code 2)

AWS Time-Synchronization Protocol:

TIME SYNCHRONIZATION REQUIREMENT:

To synchronize server and mobile device clocks:
1) Enter current 6-digit code into MFA code 1 field (e.g. `781371`).
2) Wait 30 seconds until app rotates to the next code.
3) Enter second 6-digit code into MFA code 2 field (e.g. `717896`).
4) Click **Add MFA** -> Success status: "MFA device assigned successfully."

  1. Click Sign Out in top right console menu.
  2. Navigate to AWS Sign-In page -> Enter Root Email & Password -> Click Sign In.
  3. AWS interrupts sign-in flow with prompt: 
    Multi-factor authentication (MFA)
Enter the 6-digit code generated by your authenticator app.
  4. Open Google Authenticator app -> Type current active code (`781371`) -> Click Submit.
  5. Result: Sign-in succeeds! Account is now protected by 2-factor authentication.

8. 🗑️ How to Disable & Remove an Assigned MFA Device

Decommissioning Procedure:

  1. Security credentials -> Multi-factor authentication (MFA).
  2. Select active MFA device (`MyTablet`) -> Click Remove -> Confirm removal.

9. 🛠️ Step 3 — Enabling MFA for Individual IAM Users (`sourav`)

  1. IAM Console → Users → Select sourav → Select Security credentials tab.
  2. Under *Multi-factor authentication (MFA)* → Click Assign MFA device.
  3. Device Name: "sourav-phone" | Type: Authenticator app.
  4. Scan QR Code → Enter 2 consecutive TOTP codes → Click Assign MFA.

10. 🧪 Practical Test 2 — Live IAM User Sign-In with MFA Verification

Open IAM Sign-In URL in incognito tab -> Enter Account ID, Username `sourav`, and Password -> AWS prompts for MFA Code -> Enter active Google Authenticator code -> Sign-in successful!

12. ❓ Interview Questions

Q1. Why does AWS require entering TWO consecutive MFA codes when configuring an Authenticator app?

To synchronize the internal clock of the TOTP app on the mobile device with AWS authentication servers, validating time drift and secret key alignment.

Q2. Can you enforce mandatory MFA for all IAM users using IAM policies?

Yes. You can attach a policy with an explicit `Deny` statement conditional on `"aws:MultiFactorAuthPresent": "false"`, blocking all API actions until the user authenticates with MFA.

Q3. What types of MFA devices are supported by AWS IAM?

1) Virtual Authenticator apps (TOTP e.g. Google Authenticator), 2) FIDO2 / WebAuthn security keys (e.g. YubiKey), and 3) Hardware TOTP tokens.

Q4. What happens if a Root User loses their physical MFA device?

The Root User must undergo the AWS Account Recovery process, verifying identity via registered email address and phone number confirmation to reset root MFA.

Q5. Is MFA configuration regional or global?

MFA configuration is global because IAM is a Global Service. Enabling MFA on a user protects sign-in access across all AWS regions worldwide.

14. 🎓 MFA Security Architecture Summary

Multi-Factor Authentication provides an un-compromisable security barrier, protecting Root and IAM accounts against credential theft and unauthorized access across all AWS global regions.

1. 🖥️ Why AWS CLI? (Overcoming Web UI Changes & Automating 10+ Instances)

Instructor Gaurav Sharma's Automation Explanation:

The GUI Bottleneck:

"If you need to launch 10 EC2 instances or automate CI/CD deployments, clicking around in the AWS Web Console is slow and prone to errors. Furthermore, whenever AWS updates its Web UI, browser automation scripts (Selenium) break.
The Solution: Use **AWS CLI**! Terminal commands remain constant, scriptable, fast, and completely immune to UI design changes."

2. 🔑 Programmatic Authentication (Access Key ID & Secret Access Key)

Credential Pair Anatomy:

  • Access Key ID (Public Identifier): Analogous to an IAM Username (e.g. `AKIAIOSFODNN7EXAMPLE`).
  • Secret Access Key (Private Secret): Analogous to a Password (e.g. `wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY`). Must NEVER be committed to Git repositories!

  3. Permissions: Attach AdministratorAccess or AmazonEC2FullAccess policy.
  4. Go to User → **Security credentials** tab → Click Create access key.
  5. Select use case: Command Line Interface (CLI) → Check confirmation box → Click Next.
  6. Click Download .csv file to save credentials locally. Click Done.

AWS Tutorials - 57 - What is AWS Roles & How to use AWS Cli without Access Id and Secret key

1. 🧠 Conceptual Clarity — Users vs Groups vs Roles Breakdown

Instructor Gaurav Sharma's Fundamental Clarification:

Clearing Up Common Beginner Confusion:

"A role is NOT 'Gaurav is a Developer'. That job title concept belongs to IAM User Groups!
• **IAM User:** A physical human identity (e.g. Gaurav, Sourav).
• **IAM Group:** A collection of human users (e.g. `Developer`, `Admin`).
• **IAM Role:** An identity created to be **assumed by an AWS Resource** (e.g. EC2 instance, Lambda function, ECS container). Roles have NO permanent passwords or access keys—they grant **temporary security credentials** dynamically!"

2. 🔓 The Hardcoded Credentials Security Risk on EC2 Instances

Security Vulnerability Analysis:

THE HARDCODING SECURITY FLAW:

If you run `aws configure` inside an EC2 instance, Access Keys are saved in plain text in `~/.aws/credentials`. If an attacker compromises the web server or an unauthorized user gets SSH access, they can read `cat ~/.aws/credentials` and steal permanent AWS credentials!
Storing static access keys inside EC2 servers is strictly forbidden in production!

3. 🛡️ Solution — AWS IAM Roles for EC2 (Instance Profiles)

Instead of passing static credentials to a server, attach an **IAM Role** directly to the EC2 instance. The server automatically receives temporary security tokens directly from AWS!

4. 🛠️ Step 1 — Create IAM Role in Console (`EC2-CLI-Access-Role`)

  1. IAM Console → Left Navigation → Roles → Create role.
  2. Trusted entity type: Select AWS service.
  3. Use case: Select EC2 → Click Next.
  4. Permissions policies: Search and check AmazonEC2FullAccess → Click Next.
  5. Role name: Enter "EC2-CLI-Access-Role" → Click Create role.

5. 🔗 Step 2 — Attach IAM Role to EC2 Instance (`Actions -> Security -> Modify IAM role`)

  1. EC2 Console → Select target EC2 Instance.
  2. Click Actions → Security → Modify IAM role.
  3. Select IAM role: Choose EC2-CLI-Access-Role.
  4. Click Update IAM role.

6. 🧪 Step 3 — Verification Test (Zero Credentials Stored, Full API Success!)

  1. SSH into EC2 instance → Delete credentials folder: rm -rf ~/.aws.
  2. Execute CLI command without static keys: 
    $ aws ec2 describe-instances --region ap-south-1
  3. **SUCCESS RESULT:** Command executes cleanly and returns instance details! Zero static access keys stored on disk, zero security compromise risk!

12. ❓ Interview Questions

Q1. Why is it a bad security practice to store AWS Access Keys inside an EC2 instance?

Because access keys saved on disk in `~/.aws/credentials` are permanent. If an attacker compromises the server or an insider gets SSH access, they can steal the keys and compromise the entire AWS account.

Q2. How does an IAM Role grant permissions to an EC2 instance without static credentials?

AWS Security Token Service (STS) dynamically generates short-term temporary security credentials and injects them into the EC2 instance via the Instance Metadata Service (IMDS).

Q3. How do you attach or modify an IAM Role on a running EC2 instance?

In the EC2 Console, select the instance -> Actions -> Security -> Modify IAM role, choose the role, and click Update IAM role.

Q4. What is the fundamental difference between an IAM Group and an IAM Role?

An IAM Group is a collection of IAM Users (humans). An IAM Role is an identity intended to be assumed by AWS services (e.g. EC2, Lambda) or cross-account identities to obtain temporary credentials.

Q5. What is Attribute-Based Access Control (ABAC) in AWS IAM?

ABAC uses tags on IAM identities and AWS resources (e.g. `Environment=Development`) within policy Condition blocks to control access dynamically based on matching resource tags.
